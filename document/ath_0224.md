# 식단 데이터 동기화 및 UI 개선 기록 (2026-02-24)

## 1. 배경 및 목적

현재 서비스에서 사용자가 기록 페이지(`/record`)에서 식단을 추가하거나 삭제했을 때, 메인 페이지(`/`)의 상단 대시보드(오늘의 섭취 칼로리 요약)에 즉각적으로 반영되지 않는 **데이터 불일치 문제**가 있었습니다. 또한, 메인 페이지 대시보드에서 현재 섭취량만 표시되어 목표 대비 어느 정도 섭취했는지 직관적으로 알기 어려운 UI를 개선하고자 합니다.

---

## 2. 주요 개선 사항

1.  **실시간 데이터 동기화**: 기록 페이지의 모든 변경(업로드, 삭제) 발생 시 메인 페이지와 공유되는 글로벌 상태(`todayIntake`)를 갱신합니다.
2.  **데이터 최신화 보장**: 메인 페이지 진입 시 항상 최신 섭취 정보를 불러오도록 로직을 강화했습니다.
3.  **대시보드 UI 고도화**: 현재 섭취량만 보여주던 UI에서 **'목표 칼로리 / 현재 섭취량'**을 함께 표시하여 목표 달성도를 시각화했습니다.

---

## 3. 상세 수정 내용

### 3.1. 메인 페이지 로직 및 UI 수정
**대상 파일**: `src/app/page.tsx`

- **그리디한 데이터 로딩**: 기존에는 데이터가 없을 때만 가져오던 로직을, 페이지 진입 시 무조건 최신 데이터를 가져오도록 변경하여 데이터 정합성 유지.
- **체크박스 연동**: 추천 식단 체크 시 즉시 최조 요약 API를 재호출하여 대시보드 수치 갱신.
- **UI 업데이트**: 목표 칼로리와 현재 칼로리를 병기하도록 렌더링 로직 수정.

```tsx
// AS-IS
<span className="text-lg font-extrabold text-slate-800 leading-none">
  {Math.round(todayIntake?.total_calories_kcal || 0)}
</span>

// TO-BE
<span className="text-lg font-extrabold text-slate-800 leading-none">
  {Math.round(todayIntake?.target_calorie || 0)} / {Math.round(todayIntake?.total_calories_kcal || 0)}
</span>
```

### 3.2. 기록 페이지 동기화 로직 추가
**대상 파일**: `src/app/record/page.tsx`

- **글로벌 상태 주입**: `useDietStore`의 `setTodayIntake`를 사용하여 상단 요약 정보 동기화.
- **이벤트 트리거**: `handleDeleteDayRecords`(전체 삭제), `handleDeleteRecord`(개별 삭제), `handleImageUpload`(음식 등록) 성공 시, 선택된 날짜가 '오늘'일 경우 `getTodayIntake()`를 호출하여 대시보드 정보를 동기화합니다.

### 3.3. 식단 선택 버그 수정 (중복 메뉴 이름 처리)
**대상 파일**: `src/store/index.ts`

- **문제 원인**: 기존 `isSameFood` 로직이 `menuId`가 다르더라도 메뉴 이름이 같으면 동일한 항목으로 간주하여, 서로 다른 식당의 같은 메뉴(예: '불고기')를 동시 선택할 수 없었던 현상.
- **해결 방법**: `isSameFood` 비교 시 `menuId` 우선순위를 높이고, `menuId`가 없을 경우에만 이름과 **식당 이름(`restaurant_name`)**을 함께 비교하도록 로직을 강화했습니다.
