- 원인: 프론트엔드에서 한글 라벨(예: "거의 운동 안 함")을 그대로 전송했으나, 백엔드는 특정 영문 키(`sedentary`, `light` 등)를 기대함.

    - `updateUserActivity` API 호출 시 한글 라벨 대신 영문 키를 전송하도록 수정.

```typescript
const ACTIVITY_LEVELS = [

        label: "거의 운동 안 함",
        // ...
    },
    // ...

```

## 2. 목표 설정 (Goal) 업데이트 누락 수정

- 원인: "설정 완료" 버튼 클릭 시 `updateUserActivity`만 호출하고, 목표 변경을 위한 `updateUserGoal` API를 호출하지 않음.

- **변경 사항**:

    - BMR이 없는 경우(User Profile 정보 부족 시) 기본값 또는 추정 공식을 사용하여 `targetCalorie`를 계산한 후 전송.

```typescript
// BMR 및 목표 칼로리 계산

const [resActivity, resGoal] = await Promise.all([
    updateUserActivity(userNumber, selectedLevel.key),
```

## 3. 체성분 상세 모달 BMR 표시 오류 수정

### 문제점
- 마이페이지 체성분 상세 모달에서 기초대사량(BMR)이 실제로는 데이터가 있음에도 "-"로 표시됨.
- 원인: API 응답 구조 상 BMR이 최상위 객체뿐만 아니라 `values` 내부 객체에 있을 수 있는데, 프론트엔드 컴포넌트는 최상위 객체만 확인하고 있었음.

### 수정 내역
- **파일**: `src/components/mypage/MypageDetailModal.tsx`
- **변경 사항**:
    - `inbodyData.bmr`가 없을 경우 `inbodyData.values.bmr`를 확인하도록 폴백(Fallback) 로직 추가.

```typescript
{formatValue(inbodyData?.bmr || (inbodyData as any)?.values?.bmr, "kcal")}
```

## 4. 백엔드 목표 저장 로직 개선 (CORS/500 에러 해결)

### 문제점
- 목표 설정 시 `500 Internal Server Error` 및 `CORS` 오류 발생.
- 원인: `/api/user/goal` 엔드포인트가 **AI 식단 생성**을 완료한 후에야 목표를 DB에 저장(`commit`)하도록 되어 있었음.
- AI 식단 생성(OpenAI API)이 실패하거나 타임아웃 되면 목표 저장도 덩달아 실패(Rollback)되는 구조.

### 수정 내역
- **파일**: `food_plan_backend/app/main.py`
- **변경 사항**:
    - `upsert_user_goal` 함수에서 **목표 저장을 위한 `db.commit()`을 AI 식단 생성 전으로 이동**.
    - AI 식단 생성 로직을 `try-except`로 감싸서, AI 생성이 실패하더라도 목표 저장은 유지되고 에러 없이 응답하도록 개선.
    - AI 생성이 성공할 경우에만 `UserDietPlan`을 추가로 저장하도록 로직 분리.
